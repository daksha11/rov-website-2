## Problem Statement

ROV Studios is a creative agency in Atlanta with zero content strategy. The website (rovstudios.com) is a portfolio/landing page with no blog, no SEO play, and no domain authority for content. The goal is to become the go-to creative agency in Atlanta by building an agentic AI content system that produces high-quality, SEO-optimized blog content autonomously — using Claude Max (no API costs) — with a focus on real project work as the primary content source.

## Demand Evidence

- ROV Studios is an existing agency with paying clients. The demand is for inbound leads via organic search, not a new product.
- Atlanta businesses actively search for "web design agency atlanta," "best website design atlanta," and related queries. These have clear commercial intent.
- The agency currently relies on referrals and portfolio alone. Zero organic search presence for content-based queries.
- The founder identified that real client work (case studies, design decisions, measurable results) is the unfakeable content moat. AI content farms cannot produce "How We Redesigned [Client X]'s Site and Increased Conversions 40%."

## Status Quo

Nothing. No blog. No content calendar. No SEO strategy. The site is a portfolio. This is a clean starting position — the system starts from zero domain authority.

## Target User & Narrowest Wedge

**Target user:** Atlanta business owners and marketing managers searching for a web design/development agency.

**Narrowest wedge:** Web design/development content cluster. This is what ROV sells, what they do daily, and what their target clients search for. Expansion to AI news, dev news, and design world news comes AFTER establishing domain authority on the core topic.

## Constraints

1. **No API costs.** The user has Claude Max. The entire system must run on Claude Code CLI (`claude -p`), Claude Code scheduled agents, and Claude Code skills. No separate API key, no per-token charges.
2. **Not slop.** Content must be high enough quality to represent a creative agency. Anti-slop guidelines must be baked into the system as enforceable rules.
3. **Semi-autonomous with hybrid publishing.** Trending/news content auto-publishes immediately. Case studies and project content go through a human review queue before publishing.
4. **Single topic cluster first.** Web design/development. Expand only after domain authority is established (target: 90 days).
5. **Atlanta geo-signals in every post.** Every piece of content must reinforce geographic authority, regardless of topic.
6. **Must run on Windows 11.** The user's development environment.

## Premises

1. Start with ONE topic cluster (web design/dev), expand after establishing domain authority — not launch across all topics simultaneously.
2. **REVISED:** Hybrid publishing model. AI auto-publishes trending/news content. Human reviews case studies and project content before publishing. (Revised from "human reviews everything" based on second opinion challenge about review backlog killing adoption.)
3. Highest-value content is "work-to-content" — turning real ROV projects into case studies, design breakdowns, and process posts. Not generic topic takes.
4. Multi-channel distribution — blog + social repurposing + GEO (Generative Engine Optimization — structuring content for citation by AI search engines like ChatGPT, Perplexity, and Google AI Overviews).
5. Own the infrastructure — Claude Code + own codebase + own CMS. No third-party AI SEO platform dependency.

## Cross-Model Perspective

An independent Claude subagent reviewed this session cold. Key findings:

### CMS Integration Matrix

How `/rov-publish` pushes content depends on the CMS:

| CMS | Publishing Method | Notes |
|---|---|---|
| **WordPress** | REST API (`/wp-json/wp/v2/posts`) | Built-in, just needs auth token. Best supported path. |
| **Webflow** | CMS API (requires paid plan) | Needs site API token. Free plan does not include API access. |
| **Ghost** | Admin API | Straightforward. Needs admin API key. |
| **Custom/static (Astro, Hugo, Next.js)** | Write markdown to repo, git push triggers deploy | No API needed. `/rov-publish` writes a file and commits. |
| **No blog exists** | Add a blog section first (Step 0) | Recommend WordPress or Ghost for easiest API integration. |

### Review Queue

Case studies that require human review before publishing use this concrete flow:

1. `/rov-draft` writes the post to `/projects/review-queue/` as a markdown file
2. You open the file, read it (target: 2-minute skim)
3. Run `/rov-publish --approve <filename>` to push to CMS
4. Or edit the file first, then approve
5. Posts older than 7 days in the queue get flagged as stale

### Skill Specifications

**`/rov-brief`** — Interactive project brief helper. Walks you through the Project Brief Schema fields one by one via prompts, validates completeness, and writes the brief to `/projects/intake/`. Input: interactive Q&A. Output: a completed brief markdown file.

**`/rov-draft`** — Takes a brief from `/projects/intake/`, generates a full blog post with SEO metadata, applies anti-slop rules, and writes output to `/projects/review-queue/` (for case studies) or passes to `/rov-publish --auto` (for news). Input: brief file path. Output: markdown blog post with frontmatter.

**`/rov-news`** — Searches for trending web design/AI/dev topics via WebSearch MCP tool, selects the most relevant to Atlanta creative businesses, drafts a post, runs anti-slop verification, and auto-publishes. If no topic meets quality threshold or WebSearch is unavailable, skips and logs. Input: none (autonomous). Output: published post or skip log.

**`/rov-publish`** — Pushes a post to the CMS. Two modes: `--auto` (publish immediately) and `--review` (write to review queue). Runs anti-slop verification before any publication. Handles CMS-specific integration per the CMS Integration Matrix. Input: markdown file + mode flag. Output: published URL or queued file path.

**`/rov-social`** — Takes a published blog post and generates platform-specific text variants. LinkedIn: professional tone, 1-3 paragraphs. Twitter/X: thread format, 2-4 tweets. Instagram: caption + hashtags only (no image generation). Input: blog post URL or file. Output: text ready to copy-paste or auto-post.

**`/rov-analytics`** — Reads GSC data and generates a content performance report. In Phase 3, GSC data is manually exported as CSV and fed as input (avoids OAuth/service account complexity on Windows). Future: automate via GSC API with service account if warranted. Input: GSC CSV export. Output: performance report + content strategy recommendations.

### Anti-Slop Enforcement (Two Layers)

**Layer 1: Generation-time.** Anti-slop rules are embedded in every content-generating skill's prompt (`/rov-draft`, `/rov-news`). This prevents slop from being generated in the first place.

**Layer 2: Publish-time verification.** `/rov-publish` runs a hard check before any post goes live. This catches anything that slipped through the prompt layer. Both layers run in sequence — generation guides, publish-time verifies.

1. **Banned phrase scan:** String-match against the banned phrases list. If any match, block publication and log the violation.
2. **Required element check:** Verify at least one specific number/date/result, at least one Atlanta/Georgia reference, and at least one real example.
3. **If verification fails on auto-publish:** Post is routed to review queue instead of going live. Never publish a post that fails the check.

### Anti-Slop Skill Guidelines

Every content-generating skill will include these rules:

**Banned phrases:** "in today's digital landscape," "leverage," "cutting-edge," "seamless," "elevate your brand," "digital transformation journey," "unlock the potential," "game-changer," "next-level"

**Required elements:**
- At least one specific number, date, or measurable result per post
- Atlanta/Georgia geographic reference in every post
- Real example or case reference (not hypothetical)
- Direct, conversational tone — write like talking to a smart business owner

**Structure rules:**
- Title under 60 characters, includes primary keyword
- Meta description under 155 characters, includes city name
- H2/H3 hierarchy for featured snippet eligibility
- FAQ section at bottom for GEO (AI search citation) optimization
- Schema markup (Article, LocalBusiness, FAQ) — Phase 2 task, contingent on CMS. Not required for Phase 1.
